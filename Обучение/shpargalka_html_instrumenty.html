Шпаргалка по полезным HTML‑инструментам

Не только «сайт» и «лендинг». Ниже — основные форматы, которые можно собрать в одной HTML‑странице: что они делают, когда полезны и пример применения.

Главный принцип: хороший веб‑инструмент отвечает на один из вопросов — найти → понять → посчитать → сравнить → выбрать → сделать → проконтролировать.
ПОНЯТЬ

Сайт

Несколько связанных разделов по одной теме или организации.

Пример: сайт компании: услуги, оборудование, объекты, документы, контакты.
Когда: информации много и она делится на разделы.
ПОНЯТЬ

Лендинг

Одна страница, которая последовательно раскрывает одну идею или предложение.

Пример: презентация нового датчика: проблема → решение → характеристики → кейсы → заявка.
Когда: нужно продать или понятно объяснить одну вещь.
ПОСЧИТАТЬ

Калькулятор

Пользователь вводит числа, система сразу считает результат.

Пример: длина линии + число датчиков + кабель → падение напряжения и требуемый блок питания.
Когда: есть формула или повторяющийся расчёт.
ВЫБРАТЬ

Конфигуратор

По параметрам собирает подходящую комплектацию.

Пример: объект → длина трассы → температура → число датчиков → рекомендуемые кабели, БП и усилители.
Когда: итог зависит от нескольких характеристик.
СДЕЛАТЬ

Пошаговый мастер / Wizard

Ведёт человека по процессу шаг за шагом и не даёт потеряться.

Пример: сборка датчика: QR → подготовка → сборка → фокусировка → тест → калибровка.
Когда: важна правильная последовательность действий.
КОНТРОЛЬ

Дашборд

Показывает текущее состояние системы на одном экране.

Пример: 89 датчиков: норма / предупреждение / авария, графики, последние события.
Когда: надо быстро понять «что сейчас происходит».
КОНТРОЛЬ

Трекер

Следит за прогрессом или изменением показателей во времени.

Пример: тренировки: подтягивания по дням, рекорд, цель, серия занятий.
Когда: важна динамика, а не одно значение.
СДЕЛАТЬ

Планировщик

Помогает разложить действия по времени.

Пример: монтаж объекта: люди, этапы, даты, зависимости, дедлайны.
Когда: нужно управлять будущими действиями.
СДЕЛАТЬ

Чек‑лист

Короткий перечень обязательных действий с отметками выполнения.

Пример: выезд инженера: приборы, кабели, фото, контроль питания, акт.
Когда: ошибка чаще возникает из‑за пропуска шага.
СДЕЛАТЬ

Интерактивная инструкция

Текст + фото + раскрывающиеся подсказки + проверки.

Пример: монтаж гидронивелира с кнопкой «что проверить, если показания нестабильны».
Когда: обычный PDF слишком неудобен.
НАЙТИ

Справочник

Быстрый доступ к большому набору коротких сведений.

Пример: типовые неисправности датчиков → симптомы → причины → решение.
Когда: человек знает, что ищет, но не помнит детали.
НАЙТИ

База знаний

Связанные инструкции, статьи, схемы, FAQ и документы.

Пример: внутренняя база компании по монтажу, ремонту, настройке и объектам.
Когда: знаний уже много и они постоянно накапливаются.
НАЙТИ

Каталог

Карточки объектов с фильтрами и сортировкой.

Пример: каталог датчиков: номер, версия, дата выпуска, статус, ремонт, объект.
Когда: есть много однотипных сущностей.
НАЙТИ

Карта

Показывает информацию, привязанную к местности.

Пример: объекты мониторинга на карте России со статусом каждого объекта.
Когда: география сама по себе важна.
ПОНЯТЬ

Таймлайн

Последовательно показывает события по времени.

Пример: история объекта: монтаж → авария → ремонт → поверка → модернизация.
Когда: важно понимать причинно‑следственную последовательность.
СРАВНИТЬ

Сравниватель

Ставит варианты рядом по одинаковым критериям.

Пример: три модели модема: температура, протокол, питание, цена, дальность.
Когда: вариантов немного, но параметры отличаются.
ВЫБРАТЬ

Матрица решений

Оценивает варианты по нескольким критериям и весам.

Пример: выбрать подрядчика по цене, сроку, опыту, риску и гарантии.
Когда: решение многокритериальное и «на глаз» спорное.
ВЫБРАТЬ

Дерево решений

Вопрос → ветка → следующий вопрос → конкретное действие.

Пример: «датчик не отвечает» → есть питание? → есть RS‑485? → адрес виден? → действие.
Когда: диагностику можно формализовать.
ВЫБРАТЬ

Навигатор по теме

Начинает не с разделов, а с вопроса «что тебе сейчас нужно?».

Пример: «Я проектирую / монтирую / ремонтирую / анализирую данные» → свой набор инструментов.
Когда: пользователь не знает, в каком разделе искать.
НАЙТИ

Поиск по собственной базе

Ищет по документам, карточкам или журналу.

Пример: вводишь «ДГН‑19 0247» → вся история сборки, ремонта и объектов.
Когда: данных столько, что меню уже не спасает.
СДЕЛАТЬ

Форма / анкета

Структурированно собирает данные от пользователя.

Пример: акт осмотра: объект, дата, показания, фото, замечания, подпись.
Когда: важно получать однотипные данные без хаоса.
ПОНЯТЬ

Тест / опрос

Несколько вопросов → результат, оценка или рекомендация.

Пример: оценка готовности объекта к автоматизированному мониторингу.
Когда: вывод зависит от ответов пользователя.
СДЕЛАТЬ

Генератор

Из введённых данных создаёт готовый результат.

Пример: параметры объекта → готовое техническое задание или акт в шаблоне.
Когда: много однотипных документов или текстов.
ПОСЧИТАТЬ

Симулятор

Меняешь параметры и сразу видишь последствия.

Пример: изменяешь жёсткость грунта → видишь прогноз осадок и индекс состояния.
Когда: важно исследовать «что будет, если…».
КОНТРОЛЬ

Монитор / пульт

Показывает состояние объектов и выделяет отклонения.

Пример: зелёный — норма, жёлтый — тренд, красный — превышение порога.
Когда: система работает постоянно и требует реакции.
КОНТРОЛЬ

Канбан

Карточки перемещаются между стадиями процесса.

Пример: датчики: подготовка → сборка → тест → калибровка → готово.
Когда: нужно видеть поток работы.
КОНТРОЛЬ

Журнал

Хронологические записи с поиском, фильтрами и ответственными.

Пример: журнал обслуживания оборудования: кто, когда, что делал, какие были значения.
Когда: нужна история и ответственность.

Сильные комбинации

Производство:
Wizard + чек‑лист + QR + журнал + дашборд.
Мониторинг:
Карта + дашборд + графики + таймлайн + уведомления.
Выбор решения:
Фильтры + сравниватель + матрица решений + калькулятор.
Техническая поддержка:
Справочник + дерево диагностики + поиск + журнал ремонтов.
Обучение:
Инструкция + тест + прогресс + подсказки + чек‑лист.
Научный проект:
Дашборд + симулятор + сравнение «модель ↔ факт» + таймлайн.
Шпаргалка: выбирай формат не по внешнему виду, а по задаче пользователя.
